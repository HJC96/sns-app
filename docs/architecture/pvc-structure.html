PVC 데이터는 어디에 저장될까

postgres.yaml의 postgres-pvc를 기준으로, 데이터가 실제로 놓이는 곳과 파드가 죽었을 때의 동작을 그렸습니다. rustfs도 같은 방식입니다.

만들어지는 순서

  1. YAML 제출kubectl apply로 보낸 YAML을 API Server가 받아 etcd에 저장합니다. 여기에 남는 것은 PVC 같은 오브젝트 정보뿐입니다.
  2. PVC 생성postgres-pvc(1Gi, ReadWriteOnce)가 만들어집니다. Kind의 기본 StorageClass는 파드가 노드에 배치될 때까지 PVC를 Pending으로 둡니다.
  3. 폴더와 PV 생성스케줄러가 파드를 노드에 배치하면, StorageClass(rancher.io/local-path)가 그 노드에 폴더를 만들고 PV를 생성해 PVC와 묶습니다.
  4. 마운트kubelet이 그 폴더를 컨테이너의 /var/lib/postgresql/data에 연결합니다. Postgres가 쓰는 파일은 이 폴더에 쌓입니다.

파드가 죽으면

알아둘 점

  • 폴더 위치는 노드 구성에 따라 달라집니다. lite 프로필(노드 1개)은 control-plane 노드 안에, full 프로필(워커 2개)은 파드가 배치된 워커 안에 만들어집니다.
  • local-path로 만든 PV는 특정 노드에 고정됩니다. 파드는 그 노드에만 다시 배치되고, Kind 클러스터를 삭제하면 노드와 함께 데이터도 사라집니다.
  • PVC를 삭제하면 PV와 노드 폴더도 함께 지워집니다(기본 StorageClass의 reclaimPolicy가 Delete). 파드만 삭제하면 데이터는 남습니다.
